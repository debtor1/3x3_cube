# 십자가 풀이 탐색이 한계를 넘으면 화면이 통째로 사라진다

**Symptom**: `lib/cube/cross.ts`의 `searchPlacement`는 `MAX_DEPTH`(8)수 안에 모서리 조각을 올리지 못하면 `Error`를 던진다. `components/cube/cross-trainer.tsx:63`의 `start()`는 이 예외를 잡지 않으므로, 예외가 나면 React 렌더 경계까지 올라가 색 입력 화면이 빈 화면이 된다. 아이는 길 찾기를 눌렀는데 아무것도 남지 않은 화면을 보게 된다.

**Observed evidence**: 실제로 예외를 재현하지는 못했다. 무작위 30수 스크램블 3000판을 돌려(시드 20260917, `bun run` 약 12초) 실패 0건, 풀이 최장 18수를 확인했다. 즉 지금 아는 범위에서는 8수 한계에 닿지 않는다. 다만 한계를 수학적으로 증명한 것은 아니고, 예외가 아무 곳에서도 잡히지 않는 코드 경로는 그대로 남아 있다.

**Suspected cause**: `searchPlacement`가 너비 우선 탐색의 깊이 상한을 넘겼을 때 호출자에게 실패를 알리는 수단이 예외뿐이고, `start()`는 성공을 전제로 `setMoves(solveWhiteCross(facelets))`를 바로 호출한다. 검증을 통과한 입력은 모두 풀 수 있다는 가정(`docs/specs/white-cross-guide/spec.md`의 미룬 지점)에 기대고 있다.

**What was tried**: 3000판 재현으로 주 경로가 실제로 깨지는지 확인했고 깨지지 않았다. 프로젝트의 검증 예산(AGENTS.md)이 수용 기준을 깨거나 주 경로가 실제로 깨지는 것만 고치도록 하므로 코드는 그대로 두었다. 8수 한계와 예외 경로는 바뀌지 않았다.

**Proposed next step**: `start()`에서 `solveWhiteCross` 호출을 감싸고, 실패하면 아이가 읽을 수 있는 한 줄(예: "이 큐브는 지금 길을 찾지 못했어요. 색을 다시 확인해 주세요.")을 기존 `Alert` 자리에 띄운다. 그러면 회전 패리티 검증을 미뤄 둔 상태에서 통과한 입력이 실제로는 풀 수 없는 큐브였을 때도 빈 화면 대신 안내가 남는다.
